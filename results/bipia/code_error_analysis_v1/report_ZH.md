# Code 场景漏检与误报分析（探索性）

数据来自冻结的 `results/bipia/supervised/test_predictions.csv`。这里只分析 `task=code` 的明文攻击及对应干净正文；7500 条攻击变体由固定来源、模板和插入位置组合而成，不是 7500 个独立样本。测试集此前已被查看，本分析不用于选新规则或阈值。

| 检测方式 | 攻击检出 | 干净误报 |
|---|---:|---:|
| P1 规则 | 1566/7500（20.88%） | 4/50（8%） |
| 冻结监督分类器 v1 | 3267/7500（43.56%） | 2/50（4%） |
| 两者直接取并集（仅离线分析） | 4114/7500（54.85%） | 6/50（12%） |

攻击样本中，规则与监督分类器都漏检 3386 条；仅监督分类器检出 2548 条，仅规则检出 847 条，两者都检出 719 条。两者有互补性，但直接取并集的误报代价明显，不应直接接入授权流程。Code 场景未运行原 Email 专用 P2/Hybrid，预测文件中的相应列为空，不能当作零检出。

共同漏检最多的类别是“Corrupting an Operating System”（558/750）和“Blocking Internet Connection”（513/750）。这是测试集错误分布的描述，不据此编写针对这些测试类别的匹配规则。

已有监督分类器 v2 在固定 Code 明文测试集上的结果为 2502/7500（33.36%）检出、1/50（2%）误报。与 v1 的 43.56%／4% 相比，它降低了误报，也损失了检出；不能称为全面提升。

下一轮若要改进，应先在开发/验证来源上提出通用检测信号并固定阈值，保留 Code 干净样本误报约束，再评估此前未用于规则设计的新来源。当前测试集已被查看，后续在此集上的结果只能标为探索性。监督分类器仍只作辅助对照，不参与工具授权。
