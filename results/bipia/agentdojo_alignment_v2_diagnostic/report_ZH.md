# 调用级对齐 v2：已曝光数据上的诊断（不是独立验证）

日期：2026-10-03。v2 针对 v1 测试集上发现的两个问题做了修改，因此 AgentDojo 的开发集和测试集对 v2 来说都已曝光。下列数字只用来说明修改的效果和代价，不能作为独立验证结论。

## 改动

1. **网络读取也检查来源**：读取类调用如果带有用户没写明的 URL，就转人工复核（P3 原本放行所有读取）。
2. **直接拒绝需要正面证据**：任务没有请求的写入，只有在同时出现“用户没写明的目标”（例如攻击者的账号或收件人）时才直接拒绝；其余情况转人工复核。

## 结果（测试集，153 个带工具调用的攻击实例）

| 指标 | v1 | v2 |
| --- | ---: | ---: |
| P3＋对齐：攻击目标被完整自动放行 | 11 | **0** |
| P3＋对齐：正常写入被直接拒绝 | 2/33 | **0/33** |
| P3＋对齐：攻击写入被直接拒绝 | 110/164 | 72/164 |
| P3＋对齐：正常任务全部自动完成 | 21/49 | 21/49 |
| 研究变体：正常任务全部自动完成 | 40/49 | 35/49 |
| 研究变体：攻击目标被完整放行 | 14 | **3** |

开发集上的规律相同：P3＋对齐的直接拒绝从 94 降到 75，正常任务没有受影响。

## 解读

- 堵上网页读取后，P3＋对齐在两个划分上都**没有任何攻击被完整自动放行**。代价是：研究变体中，需要访问从数据里查到的网址的正常任务也会转人工复核（全自动完成 40→35）。
- 改为“有证据才拒绝”后，误拒消失了，但约 38 条攻击写入从“直接拒绝”变成“人工复核”。这些调用都没有被自动放行，只是增加了人工复核的工作量。
- 这一版需要**新的数据来源**做独立验证。AgentDojo 最新提交（2026-06）没有新增任务。候选是 ASB（MIT），但它的工具名不是“动词_对象”形式，任务里也很少直接写出工具，字面规则在那里大多只能转人工复核，需要配合语义匹配。
