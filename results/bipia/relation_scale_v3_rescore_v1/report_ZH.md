# v3 参考事后重算：分数没有上升，说明 v3 不是为迎合输出而定

日期：2026-10-03。把已经核验过的五配置原始输出（v2 提示生成）与 v3 参考重新比较。**未推理、未训练，不替代 v1 主指标。** 规范是在看过这些输出之后确定的，本结果只是事后诊断。

## 方法

- 参考来自 `data/bipia/relation_scale_targets_v3/`：136个核心参考中改了76个，验证集24个侧输入中改了8个。
- 预测保留 v2 下的有效性判定。v2 提示从未要求 claims，因此补 `claims=[]`；也不对预测施加 v3 的占位与顺序词校验，因为生成时并未要求。
- 分母与 v1 相同：每配置6任务＋18正文，核心18对。

## 结果（核心）

| 配置 | 正文完整匹配 v1→v3 | 任务 v1→v3 | 双侧 | 匹配/预测/参考单元 v1 | v3 | 召回 v1→v3 |

格式变体趋势相同（见 `summary.json`）。参考单元由49增至51，原因是003、023新增了 claims。

## 逐条变化（核心）

- **001正文**：28组在 v1 下完全匹配，v3 下不再匹配；16组从3个匹配单元降到1个。原因是模型沿用了训练参考中的 v1 惯例（“执行”作操作词，“然后”作条件），说明模型学到的是训练标注本身的惯例。
- **003、023正文**：新增的 claims 单元（“方便保留结果”“便于后续自行筛选”）在 v2 提示中从未要求，属于结构性失分，所有配置都受影响。
- **022正文**：“不包含其他列”改为 prohibited 动作后，原先作为约束匹配上的单元不再匹配（少样本、16组）。
- **005、021正文**：按 R4 改为 unmapped 后，28组的输出变成完全匹配。

因此28组正文完全匹配仍是2/18，只是从001、003换成了005、021。

## 解读

v3 没有把分数“改好”，这一点支持本轮规范修订是在统一规则，而不是迎合模型输出。但这也说明，现有适配器是用 v1 惯例训练的；要检验 v3 能否让模型更稳定，必须用 v3 训练参考重新训练，并在未曝光的留出组上评估。本表不能作为任何模型改进的证据。
