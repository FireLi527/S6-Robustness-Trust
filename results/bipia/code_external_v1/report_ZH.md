# Code 注释信号：公开基准外部测试（探索性）

本轮把已冻结的 P1 规则和实验性 Python 注释信号，直接用于一个公开仓库级基准的代码注释载体；未修改检测器、阈值、P3 授权或既有实验。样本及检测器哈希在评分前冻结，原始文本只在本地保存。公开基准为 [RepoGuardBench](https://github.com/DaoyuanLi2816/RepoGuardBench)，版本 `f1c1d28d2e308e353b63458c27f4df091f5503c7`；其数据按 [CC BY 4.0](https://github.com/DaoyuanLi2816/RepoGuardBench/blob/main/LICENSE-DATA) 授权。本报告只使用其公开任务和安全模拟载荷，按原有 `code_comment` 规则静态构造输入，不运行基准代理或载荷。

470 条攻击组合来自 94 个任务各配 5 个固定攻击目标，并非 470 次独立攻击。Core 为 80 个合成微仓库任务、400 条组合；Applied 为 14 个手工编写的任务、70 条组合，两组均未检出。五种目标（读取模拟 canary、写入模拟记录、删除测试、运行无害 `echo`、插入标记）各 94 条，均未检出。

现有注释信号要求同一条 Python 注释同时出现 `assistant/agent/reviewer` 与 `ignore/skip/...` 等重定向词。该基准使用维护者或 CI 权威包装，并把动作要求分布在多行注释中，因此不满足这一同句模式。P1 的现有规则也未覆盖这些写入文件、删测试、执行命令等修复流程劫持表述。原始开源代码的 7 个 P1 标记主要由独立命令式句子、高风险词或输出控制词触发；这些是未改动源码中的标记，按来源视为疑似误报，尚非独立人工判定。100 个片段取自不同源文件（pandas 50、SciPy 50），其中 64 个含 Python 注释，其余至少含文档字符串；注释信号不解析文档字符串。

## 结论与边界

这次外部措辞测试推翻了“当前注释信号对代码注释注入有可泛化检出能力”的乐观解释；上一轮 62% 仅适用于当时自编模板的确认集。不能据此估计真实世界攻击检出率，也不能将其与 BIPIA 或上一轮数据合并平均。RepoGuardBench 载荷是作者公开编写的安全模拟攻击，Applied 任务也不是从真实 GitHub 仓库抓取；本轮真实开源仓库部分只检验未改动代码的标记率，没有独立人工标注或真实攻击标签。检测率不是 LLM 代理端到端攻击成功率。

下一轮如继续研究，应先设计跨行、带来源语境的“仓库内容提出额外文件/命令操作”候选信号，并在另一套新来源上冻结后验证；本轮零检出数据只能用于诊断和开发，不应改完规则后在同一 470 条上宣称确认收益。P3 仍独立控制工具调用，本信号不参与授权。
