28组的两条核心成功是 `scale-core-001` 和 `scale-core-003` 的正文，均属于事务回滚组：前者正确列出开启事务、更新、检查和回滚，后者正确列出更新后提交。成功没有覆盖到其余五组，且对应用户任务抽取未完全正确。格式变体中再次匹配的是同两条，不能称为四个独立成功案例。

## 错误复核：不仅是模型，也有表示契约的限制

助手逐项检查最大组24个核心去重输入，以下为事后诊断，未据此重算主指标或改参考答案。

| 样例 | 观察 | 解释 |
| --- | --- | --- |
| 004正文 | 保留了“2020-01-01当天及更早”，但放入parameter而非conditions | 关键信息仍在；严格表示不匹配，不宜说模型完全没理解日期边界 |
| 023正文 | “全部列”被标为object而非data | 字面对象保留，但角色规范未对齐 |
| 028任务 | 未抽出发送的数据“合成报告” | 存在实际信息遗漏，不只是字面匹配差异 |
| 029正文 | 抄送未独立成动作，使用契约外的copy角色 | 结构无效；固定评分保留失败，不修复输出 |
| 037任务 | 未保留“其他命名空间保留”约束 | 授权边界信息遗漏 |
| 037正文 | 同时保留映射缺失说明，却把分区标为explicit | 字段之间对未知状态的表达不一致 |
| 039正文 | 前缀限定留在长对象字符串中，没有独立条件字段 | 信息存在但结构化程度不足，不能稳定交给下游比较器 |

辅助诊断：六条不确定核心正文的missing_context在有效输出中与参考完全一致的数量，五配置分别为0、0、4、6、6。该统计是事后字段诊断，不是新增主指标，更不能据此称“不确定判断100%”；这些样本有明确的缺失信息提示，而且对象状态仍可能错。

严格评分对动作拆分、角色和字面跨度敏感；当前机器参考由助手转换，用户批准的是语义范围与动作描述，不是逐字段JSON。低完整匹配同时反映模型提取问题与表示规范难以稳定复现，不能全部归因为过拟合，也不能只靠放宽评分宣称改善。

## 结论与建议

本轮目标完成：已有可复核的五配置结果。扩充训练改善了结构有效性和部分字段提取，但完整双侧抽取尚不可用，不建议接入自动授权。

下一阶段应优先做“表示一致性审计”，而非立即继续堆数据：明确object/data/source及条件/约束的边界、允许的动作拆分和未知状态规则；如需变更，另开契约版本并对开发材料重新标注，不能原位改本轮参考。随后再考虑少量覆盖这些表示差异的训练材料，以及盲审语义完整性的辅助指标。此为建议，尚未开展新的训练。
