# 第二轮开发实验结论

已完成36条合成样本的用户审核（18正常、18注入），训练一个保持原架构与参数的补数据模型，并完成全文/分块四组对照。此次没有训练或改动MiniLM，使用的仍是词和字符TF-IDF加逻辑回归。

## 两个问题要分开看

固定第一轮阈值0.5378236，只观察补数据的影响：

| 组别 | RepoGuard检出 | RepoGuard误报 | 已审核维护说明误报 |
| --- | --- | --- | --- |
| A 原模型全文 | 124/470（26.38%） | 1/94 | 13/30 |
| B 原模型分块 | 304/470（64.68%） | 11/94 | 13/30 |
| C 补数据全文 | 150/470（31.91%） | 1/94 | 12/30 |
| D 补数据分块 | 221/470（47.02%） | 11/94 | 12/30 |

这是基于已经保存预测作的事后固定阈值诊断，没有用它重新选模型或调阈值。补数据使全文检出增加26条，维护说明误报减少1条，但分块检出反而降低83条，不能宣称补数据全面改善。RepoGuard只有五个重复攻击模板，行数变化不是同等数量的新攻击家族。

正式开发对照的阈值规则在拟合前冻结：原验证集与新增公开验证来源的误报率都要不超过5%。在该约束下，四组阈值均升至约0.89，RepoGuard检出全部变为0/470。新增验证来源中原模型检出28/308，补数据模型31/308；这表明当前表示与训练数据在新来源上区分能力不足，提高阈值主要换来漏检。

## 本轮结论和后续方向

保留这次有限收益与负面结果，暂不将新模型接入默认检测。36条样本可以帮助纠正少量表现，但不足以支撑跨场景检测；继续增加相似模板的数量也不能直接保证泛化。下一轮应优先收集真实仓库维护内容和不同来源攻击家族，按场景验证，比较能够利用用户任务与正文关系的表示。任何新增方法都需要新的数据协议和确认集。

新增公开来源为 [Agentic Prompt-Injection 5K](https://huggingface.co/datasets/3nesdeniz/agentic-prompt-injection-5k)，作者Enes Deniz，许可CC-BY-4.0，固定版本e658d94dcafc133e3a4483f9f9aa13507f3848c4。只使用其467条验证数据；训练分片未用于拟合，测试分片没有打开或评分。它是混合场景的合成数据，不是纯仓库文件。另一候选 [Coding Agent Security Benchmark](https://huggingface.co/datasets/rogue-security/coding-agent-security-benchmark) 衡量广义代理行为违规，不能把所有违规标签直接当提示词注入，因此本轮未采用。

全部对照均是开发实验。没有独立外部确认结果，也没有真实LLM代理端到端安全结论。原始训练与测试成果保持原样。
