# S6 后续修改约束

修改任一 baseline 前先阅读 `ENGINEERING_ZH.md`。共享工程工具在 `engineering/`，两条 baseline 不得互相导入业务模块。

- 已冻结的数据、脚本、模型与哈希关联文件不得原位重构；新行为使用新模块、新实验目录，记录迁移和兼容边界。
- 新实验从仓库根目录使用 `python -m ...` 运行；禁止导入旧实验脚本或以下划线开头的内部接口。
- 运行时输入/哈希检查使用明确异常，不用 `assert`；测试断言不受此限制。
- 长文本不得静默截断。记录输入 token、分块和覆盖率；资源超限明确拒绝。
- 缓存身份包含模型权重/分词器版本、代码和编码配置，不能仅使用文本哈希。
- 实验先冻结配置与输入哈希，再训练；测试集不用于选方案。已曝光测试只能标为开发诊断，不能重新包装为独立验证。
- 实验文件原子写入，运行目录独占，失败记录原因；不覆盖旧运行，不自动清除失败标记。
- 完成后运行 `python -m s6.engineering.check`；报告已通过、跳过、受阻的检查及冻结例外。
- 保持中文沟通、前端中英文一致；不把脚本/接口检查称作视觉验收，不自动提交或推送。
