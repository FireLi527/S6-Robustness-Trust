# S6 工程标准 v1

适用层级：`s6/`，共同约束图像数据安全与提示词注入两个 baseline。研究指标、数据划分与授权策略仍由各 baseline 的版本化协议定义。

## 结构和依赖

- `engineering/`：文件完整性、原子产物、运行状态、质量检查、通用文本编码；不导入 baseline 业务代码。
- `prompt_injection/`、`data_poisoning/`：独立业务模块。新的共享逻辑放在工程层；禁止跨 baseline 裸导入同名模块。
- 新实验是编排层，不是公共库。只依赖公开模块，不导入另一个实验脚本的函数或 `_private` 接口。
- 从项目根目录通过 `python -m s6.<模块>.<入口>` 运行新入口。旧脚本保留原运行方式，不批量改写导入。
- 新公共接口提供类型标注、文档与输入检查；禁止裸 `except`、静默降级和以 `assert` 实施生产完整性检查。

## 数据和实验契约

1. 记录来源、许可、版本、标签依据、任务字段和历史曝光；保留数据分组，不能把同一对象或近重复拆到不同划分。
2. 冻结运行配置、输入及代码哈希、环境依赖版本和随机种子；先训练/验证，再根据预先固定方案评估。
3. 使用独占的新版本目录。写文件采用临时文件加原子替换，记录 RUNNING / COMPLETE / FAILED；失败后不得删除标记重新选参冒充首次评估。
4. 报告准确率、精确率、召回率、误报率及分母。单类样本不能报告不存在的指标；验证集经验误报约束不是总体保证。
5. 代码测试、数据一致性、研究收益、端到端代理成功率和视觉验收分别报告。

## 编码与缓存

- 固定本地模型快照，默认离线。权重保持冻结；记录权重/配置/词表哈希。
- token窗口必须扣除特殊符号开销，并验证不超过模型位置上限。重叠窗口覆盖正文尾部；批量推理有明确资源边界，不能静默丢弃窗口。
- 缓存键包括模型文件、算法代码、窗口/重叠/聚合配置、文本哈希。缓存损坏显式报错，不能回落到旧缓存。
- `legacy_prefix_128` 只允许作为清楚标注的研究对照；新完整输入路径用 `chunked`。
- 分块覆盖全部token不等于模型理解全文关系，也不保证检测收益；均值聚合可能稀释局部攻击，需要单独验证。

## 检查与交付

Windows 使用 `.venv-bipia\Scripts\python.exe`，GPU图像训练仍使用原WSL环境，不由工程检查触发。

```powershell
& .\.venv-bipia\Scripts\python.exe -m s6.engineering.check
& .\.venv-bipia\Scripts\python.exe -m s6.prompt_injection.experiment_long_text_v1
```

检查入口分别在子进程运行工程层、提示词注入、图像测试，避免同名模块串用；同时核验冻结保护清单和新生产代码的基础静态规则。只执行本地测试，不启动训练、下载或真实工具操作。

新模块按上述标准准入，历史模块逐步迁移。`engineering/frozen_assets.json` 是本轮起点的保护清单，不表示已全面审计所有历史产物；禁止因检查失败自动更新其哈希。历史全量文件中的异味保留在审计报告，不擅自修复冻结脚本。

本轮范围：工程入口与两条baseline边界审计，近期提示词实验及嵌入链路重点审计；不宣称整个仓库已经完成安全认证或全面重构。

## 结构审查要求

新增或修改当前运行代码时，记录重复逻辑、职责和依赖变化。函数超过80行、分支节点超过15或生产模块超过500行时应解释职责边界；这些是审查提醒，不是要求机械拆函数的硬门槛。不要为少量稳定重复强行建立公共框架。

重构需报告总代码量变化，不只报告主文件缩短；历史冻结副本与真正无用代码分开处理。删除或移动入口前确认命令调用、动态导入、前端路由和复现协议引用，不能只靠静态导入图判断。

首轮记录见 [结构与异味审计](engineering/STRUCTURE_AUDIT_ZH.md)。新参数校验模块已加入统一静态检查；后续新增运行模块也须登记检查范围并补契约测试。

## 前端异步契约

前端写回任务相关结果时，必须同时匹配输入版本和同类请求次序；错误与finally分支也必须检查所属请求，不能只保护成功分支。修改输入、切换样本、清空、范围失效时立即隐藏旧审批入口。邮件样本和工具场景共享加载次序，不能互相覆盖。

审批提交只使用点击时的参数快照；提交中防重复。输入变化后不得由旧审批响应自动触发新任务的检测。丢弃旧响应不等于撤销服务器已接受的批准，实际权限仍由服务端范围与风险检查决定。

统一检查现包含Node.js前端回归测试（需本地Node，缺失时报错，不静默跳过）。测试执行实际页面处理函数及独立请求状态模块，使用模拟DOM和可控Promise测试乱序；不能将其称为浏览器视觉验收。
