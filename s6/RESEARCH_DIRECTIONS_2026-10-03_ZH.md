# 提示词注入 baseline 后续方向（2026-10-03）

本文为建议，尚未实施。依据：本项目已有结果，以及近期文献中与“任务对齐”“能力与数据来源控制”相关的公开工作。

## 1. 我们在文献中的位置

| 本项目组件 | 对应思路 | 说明 |
| --- | --- | --- |
| P1 规则、P2 语义一致性 | 内容检测器 | 只看文本是否像注入；BIPIA 上有效，但跨来源泛化有限（见 cross_source_training_v1） |
| P3 工具权限、P3.1 用户批准 | Tool Filter、最小权限 | 与正文内容无关的确定性闸门，已把危害动作成功率从100%降到11.11% |
| 关系抽取＋比较器（研究线） | Task Shield 一类的任务对齐 | 判断正文要求的动作是否服务于用户任务；我们用本地4B模型抽取、确定性规则比较 |

近期工作：
- **Task Shield**（ACL 2025）：在执行前检查每个工具调用是否服务于用户任务。在 AgentDojo / GPT-4o 上，攻击成功率从 47.69% 降到 2.07%。作者也指出，换用较弱的模型时效果会下降，且容易受到自适应攻击。
- **RETA**（2026）：在任务对齐的基础上加入推理，以应对自适应攻击。
- **CaMeL**（SaTML 2026）：把用户查询的控制流与不可信数据分离，并给每个数据值附上来源（能力）标签，在调用工具时按策略检查。它是目前少数能给出确定性安全保证的方案，代价是需要人工编写策略。

## 2. 关键判断

1. **正文的自由文本抽取是最难的一环，而在智能体场景中它不是必需的。** 真正执行时，正文导致的动作是一个结构化的工具调用（工具名＋参数），不需要从正文里逐字段抽取。我们目前的瓶颈（正文完全匹配0–2/18）恰好落在这一环。
2. 需要可靠抽取的只有**用户任务一侧**：它通常短、来源可信，失败也更容易被用户发现和纠正。
3. 只有**确定性的来源检查**能给出可复核的保证：例如“工具参数（收件人、URL、路径）来自不可信正文、且未出现在用户任务或白名单中”就拒绝。这比依赖模型的语义判断更适合作为 baseline 的主闸门。

## 3. 推荐方向（按优先级）

### A. 调用级任务对齐（推荐，约一周可完成）

把研究线从“抽取正文”改为“比较用户任务与实际工具调用”：

- 输入：用户任务的 v3 抽取（模型）＋拟执行的工具调用（结构化，无需抽取）。
- 复用：v3 契约中的任务侧字段、已冻结比较器的优先级逻辑、P3 的工具风险分类。
- 数据：P3 已有工具场景（`tool-scenario`）；另需构造少量带“用户任务＋注入正文＋拟执行调用”的样例。AgentInjectionBench 只有文本对话、没有结构化调用，只能用作参考。
- 指标：危害调用放行率、正常调用摩擦率，与 P3 单独使用时直接对比。这是 baseline 真正关心的端到端指标。

### B. 参数来源检查（CaMeL 简化版，需你批准改 P3 才做）

在 P3 之上新增 P3.2（新版本，不改 P3）：对高影响工具的目标类参数做来源追踪。只出现在不可信正文里的值，不能自动成为收件人、URL 或写入路径。规则确定、可测试，适合作为课程展示中“可证明的边界”。

### C. 现有抽取研究线：收尾，不再扩张

完成 v3 训练、验证和留出组评估，以及比较器的判定指标并写成报告后，作为“抽取难度与表示规范”的研究结论保留。除非留出组上的判定指标明显好于预期，否则不再追加同类合成数据。

## 3.1 本轮实验完成后的安排（用户确认，2026-10-03）

依据：用户判断“主 baseline 高、其他场景低”是过拟合，并关心瓶颈是数据量还是 4B 模型。按以下顺序推进：

1. **留出组学习曲线**：用 8/16/28 组在留出组上的结果，判断规模带来的提升能否迁移到新数据；同时与验证集对比，量化样本过拟合的幅度。
2. **查已有的跨来源记录，必要时补一张冻结表**：先确认 P1、P2、混合系统是否已有不调参的跨来源结果。如果没有，就在本地已有的外部数据（InjecAgent、NotInject、AgentInjectionBench、RepoGuardBench 等）上补一张检出率、误报率表。这张表用来量化主 baseline 对数据来源的过拟合，补做前需用户决定。
3. **强模型上限探针（需用户决定）**：用更大的模型跑同一批验证数据，判断严格抽取任务本身是否可行。本地 8B NF4 勉强可行；外部 API 需要把数据发给第三方，需用户同意。
4. **转向调用级任务对齐（方向 A）**，并引入非本人编写的外部材料，不再扩充同类合成数据。

## 4. 不建议做的事

- 继续由同一作者编写同质的合成中文样例并扩大规模：类别线索明显，无法证明泛化。
- 通过调整比较器规则提高验证或留出组上的数字：违反已登记方案。
- 用研究模型直接授予工具权限：任何方向都只输出 ALLOW/REVIEW/BLOCK 建议，最终权限仍由 P3 和用户批准决定。
