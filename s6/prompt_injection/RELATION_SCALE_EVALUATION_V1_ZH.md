# 扩充训练统一开发验证 v1

日期：2026-10-03。目标是得出五配置统一可比结果，不在验证后改阈值、提示、参考字段或训练检查点。模型和数据沿用已完成的 `relation_scale_training_v1`。

## 预先固定方案

比较基础模型零样本、基础模型少样本、small_8、medium_16、large_28。模型为同一本地官方Qwen3-4B NF4快照，三个适配器为固定3轮最终权重。基础对照禁用适配器；少样本示例仅用训练材料 `scale-seed-dev2-01`。其余配置均零样本。所有配置共用原v2提示、逐动作/对象/条件的严格评分和BF16推理上下文。

完整输入、不截断；贪心解码，最多1600个新token、总预算4096，不启用语法约束，不修复JSON，不重试失败输出。验证数据共36对：18核心及18格式变体、6个任务组。任务与正文分开输入，正文抽取不能借助另一侧授权补全未知信息。

在每个配置内按“侧别＋完全相同输入文本”去重，并要求参考字段一致：6个任务输入、36个正文输入，共42次独立推理。五配置共210次推理，显式展开为360条样本侧记录；不跨配置缓存。此举避免对重复任务文本多次生成，并在指标中单独暴露重复计数。每次原始输出、实际token和输入消息均留存。

## 指标口径

- 契约有效：JSON结构和字面证据符合契约，不代表语义正确。
- 单侧完全匹配：严格参考动作、对象角色/状态、条件、约束和缺失信息全部匹配。不同但合理的抽取粒度也可能被扣分，不是语义等价评判。
- 去重单侧：每配置共42个输入；核心或格式变体子集各24个（6任务＋18正文）。
- 双侧同时正确：同一材料的任务及正文均完全匹配；核心18对、格式变体18对，分别报告。
- 严格单元精确率/召回率：匹配单元/预测单元、匹配单元/参考单元；无效输出匹配数为0，参考单元仍计入召回分母，预测为0时精确率未定义。
- 未完成输出仍算失败；重复材料不能提高去重分母，不将格式变体当作独立语义。

这些不是攻击检出率、攻击误报率或真实代理端到端成功率。无任何工具授权输出。

## 工程与复现

从项目根目录：

```powershell
wsl -d Ubuntu-24.04 -- .venv-s6-qlora/bin/python -u -m s6.prompt_injection.evaluate_relation_scale_v1
wsl -d Ubuntu-24.04 -- .venv-s6-qlora/bin/python -u -m s6.prompt_injection.verify_relation_scale_v1
```

结果目录 `results/bipia/relation_scale_evaluation_v1/` 独占创建；失败保留，不覆盖旧结果。运行前后校验受保护代码/数据和适配器；核验阶段重新计算请求、token、EOS、严格评分及汇总，核对210份原始推理与360份展开记录，不重新调用模型。

新增生产代码248行（指标67、推理111、核验70），新增8项CPU契约测试；工程检查入口另登记3个模块，旧冻结代码不变。最大函数44行。保守AST计数含推导式：聚合24、预检18、核验主流程18个分支节点超过提醒值，分别集中于多分母汇总、来源校验和产物重放；保持各自完整职责，不引入跨baseline框架。公共推理和严格评分复用冻结v2接口。

局限仍为单种子、同源合成中文、机器字段未逐字段人工审核，且规模较大同时意味着更多训练计算。所有结果属于开发验证；六个未来独立任务组尚未编写。本轮结果不触发自动部署、前端切换、权限放宽、提交或推送。
