# 弱项开发改进 v2：审批可用性与引用分析分工

本版保留已推送的v1模块、开发结果和失败确认。新增`approval_readiness_v2.py`和`experiment_readiness_routing_v2.py`，不原位修改冻结身份。

## 两项改动

审批状态提取继续要求可信任务明确依赖先前审批，补充cannot/can't/unable to access的语法、无保存记录、批示未保存和审批凭据丢失。保留已有证据、任务哈希和可用性反证；否定、分析任务和矛盾状态的契约继续检查。这仍是有限语法规则，不能证明真实审批存在或通用未知条件识别。

引用分析分工要求可信任务同时出现文字分析对象、分析意图和不执行声明。新增中文表达和英文描述改写；明显的随后执行/发送等混合意图不获得新增分析分工。只改变选用的提示词头，**不把任务规则直接映射为NORMAL**：最终NORMAL仍需由该头的模型输出产生。

`task_profile`只接收可信任务，不看正文、标签或来源。`resolve_readiness`保留实际选头模型信号、风险告警与审批准备状态，所有结果都不授予执行权限；历史模型判断另存作审计，可能因纠正引用误报而与新判断不同，不能声称选头变化后的原始告警仍完全相同。
