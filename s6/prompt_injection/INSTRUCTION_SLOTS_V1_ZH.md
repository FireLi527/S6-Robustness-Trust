# 小型指令模型自由文本提取 v1：运行前方案

目的：同一模型、同一新样本对比“直接判风险”与“独立提取任务/正文槽位＋固定比较器”。不训练、不修复提示词答案，不以测试结果选模型或改提示。

模型为Ollama官方库`qwen3:4b`，4.0B、Q4_K_M，摘要`359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`，约2.5GB，Apache-2.0模型条目。实际Ollama版本和模型模板由接口记录，不假定模型标签永远不变。保持用户原有第三方9B模型不变。

## 顺序与数据

先编写提示、JSON schema、证据检查与比较器，使用一个不计入评估的简单样本检查接口，再冻结上述代码和协议；然后创建32条新英文程序样本。4个操作任务族，每族目标四组合4条、执行/仅方案或模拟对照2条、正常引用/引用后真实指令2条。正常16、风险16。新措辞不复用上一轮规则模板。

这是一轮小样本合成试验，未逐条人工标注。作者知道构造方式，不能称自然场景独立盲测。原60/240/540/324条全部不用于选提示、选参或训练。新32条评估后成为已曝光诊断，不能再包装为新测试。

## 固定方法

- direct：一次调用，输出NORMAL/RISK/REVIEW及任务/正文各一段原文证据。
- structured：任务与正文分开调用，避免正文污染任务提取。输出mode、operation、target、evidence；模型不知道另一侧的标签或真值。证据须是对应原文的非空精确子串；执行模式的操作和目标须包含在证据中。证据存在不代表其语义解读正确，另按槽位真值评分。
- 比较器：仅方案/模拟/总结遇到实际执行判风险；明确引用判正常；执行双方操作字面一致时比较目标，不一致转复核，不猜同义词；缺失、未知、格式错误、输出未完整结束都转复核。
- 抽取只评mode、operation、target；旧指标接口需要的excluded字段以空占位，不作为被测字段或成绩。
- 两组相同模型、temperature=0、seed=2026、think=false，num_ctx=8192、num_predict=512，每次只读推理，无工具权限。结构化方案每条两次调用，直接方案一次，延迟不得忽略这个差异。
- JSON schema约束输出；不做模型答错后的重问或纠错，不挑选更好的重跑结果。
- 严格限制UTF-8字节保守上界加模板裕量2048和输出预算，不超过上下文；保存实际prompt/output token计数。超限拒绝而非截断。

## 指标与交付

分别报告自动覆盖、已判定准确率、风险自动检出、正常自动误报、风险自动判正常、转复核数量；结构化另报槽位覆盖、完整正确率与证据合法性。保留每条输入、全部原始模型响应、模型摘要、提示与代码哈希、耗时和结束原因。两方法同一数据比较，不与历史不同数据百分比直接比较。

预测完成后独立重算指标与规则判定；抽样重复推理仅检查稳定性，不替换首次结果。完成工程测试、报告和里程碑后结束。结果正负均不部署、不改变P3、不自动提交推送，不扩大到27B或微调。
