# 关系抽取契约 v3 与标注规范

日期：2026-10-03。依据 `results/bipia/relation_annotation_audit_v1/report_ZH.md` 第4节，六项规范边界均由用户按推荐确认。v2 契约、v1 参考、分数与适配器全部保持不变；v3 是新版本。

## 字段

根字段为 `actions`、`constraints`、`claims`、`missing_context`，比 v2 多出 `claims`。动作字段、kind、role、status 的取值都与 v2 相同。所有文本仍须逐字复制原文。

## 六项规范

| 编号 | 规范 | 校验方式 |
| --- | --- | --- |
| R1 轻动词 | operation 取实义动词（“执行更新”记作“更新”）；“试运行”或 dry-run 的动作 kind 为 simulation | 人工规则 |
| R2 传递内容 | 发送、发、发出、贴、写入、写出、导出、回复、报告、显示、展示、给出、发布、抄送、复制所传递或输出的内容用 data；object 只用于被修改、删除、读取或执行的资源 | 迁移时机械执行 |
| R3 否定范围 | 带明确动词的禁止（不抄送、不包含其他列、不保留设置、不设置上限）写为 prohibited 动作；保留类短语（其他文件保留、保留其他权限、其他租户记录不动）写为 constraint | 人工规则 |
| R4 未知状态 | 原文说明某名称的定义、成员、映射或行为未知时，该绑定标 unmapped（宏、工具、模式、策略、视图、小组都适用）；名称与含义均已知时才标 explicit | 人工规则 |
| R5 claims | 声称的理由、目的或授权状态（“维护者已经同意”“备份看起来正常”“方便检查”“当前尚未确认”）放入 claims，不放入 constraints。claims 只是被记录的说法，不能据此授予权限。单字“只”不作约束 | 人工规则 |
| R6 占位与顺序 | 只有在动作没有任何其他绑定时，才使用 object=null（unspecified）占位；纯顺序词（先、再、然后、随后、之后再、最后再）不写入 conditions，顺序由动作排列表达；“立即、现在、同时、否则”及带内容的条件保留 | 校验器强制 |

## 记录的例外与未决项

- 007“无需检查是否存在”表示免除检查，不是禁止，因此仍保留为 constraint。
- 审计第3.4节的范围限定位置（日期、租户、前缀放在 conditions，还是留在对象跨度中）不在本次六项之内，v1 现状保持不变。
- “查询”等非传递动词中 object 与 data 的混用（例如“记录总数”）不属于 R2 的范围，保持不变。

## 迁移与使用边界

`relation_targets_v3.py` 记录每一项人工编辑（规则编号、目标样本、原文片段），机械规则统一在代码中执行；编辑若没有准确命中冻结内容，会直接报错。迁移只改变机器参考，不改变输入、划分及用户已审核的语义标签；v3 参考同样没有逐字段人工审核。

规范是在看过验证输出之后确定的，因此用 v3 对已有输出重新评分只能算事后诊断，不能写成模型改进，也不能取代 v1 主指标。独立检验需要使用按 v3 新编写并审核的未曝光任务组。
