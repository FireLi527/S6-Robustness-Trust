# 提示词注入监督分类实验（2026-09-21）

## 本次完成范围

将本地已有 Email、Table、Code 纳入统一监督实验。没有下载新语料或微调 MiniLM；使用完整文本的词 unigram/bigram 哈希特征与 SGD 逻辑分类器。输入只有真实任务与待检查正文，攻击名称、注入位置、答案等元数据不作为特征。

原始 1,200 条记录：791 条训练、198 条验证、200 条测试，11 条训练邮件因为正文与测试重复而排除。仅按空白归一化后的正文做精确分组；这不是近重复检测。相同正文不同问题也保持在同一划分。

训练攻击类别排除与测试同名类别，text 排除了 Language Translation。训练 327,420 条攻击变体，覆盖两种编码和三个插入位置。每个原始来源的干净样本在训练中重复到与该来源攻击数量相同，属于类平衡，不是增加独立干净数据。三个任务没有额外做等权重采样，Table 占多数。

3 个固定训练轮次，仅按验证集选轮次与阈值：各任务验证干净误报率均不超过5%时，最大化三任务平均攻击召回率。选中第3轮，阈值0.79。Email 验证仅7条、Code仅10条，因此这一约束很不稳定，不能保证测试误报率。

测试集82,500条攻击变体加200条干净记录，均与训练/验证正文组分离。测试内部重复保留，不能将所有变体视为独立观测。开发/验证共享攻击模板，测试攻击类别不同。旧测试结果此前已查看，这不是全新盲测。

## 结论与使用方式

监督模型在 Code 明文攻击检出率43.56%、误报率4%，优于规则的20.88%和8%；但 Email 明文55.29%/10%、Table明文21.56%/0%，以及编码攻击结果均不足以替换规则系统。该结果说明当前词特征监督基线对新攻击和编码变化泛化不足，不能解释为所有监督学习方法都无效。

现有规则、MiniLM相似度与权限门控保持原协议。网页新增“对比监督分类器”开关，填写真实任务后可显示分类器的独立分数和复核建议。分数不是经校准的攻击概率；该结果不参与工具授权。

API 示例字段：`text`、`question`、`use_supervised: true`。响应新增 `supervised`，默认不启用；模型缺失或校验失败返回 UNAVAILABLE。此版本仅返回 ALLOW/REVIEW，不自动 BLOCK。

## 复现和证据

从项目根目录使用 `.venv-bipia/Scripts/python.exe`：

```text
python s6/prompt_injection/train_supervised.py
python s6/prompt_injection/verify_supervised.py
python s6/prompt_injection/app.py
```

训练入口拒绝覆盖已冻结模型，避免观察测试结果后悄悄重训。独立核验入口可重复运行，不重新拟合。数据协议和来源划分保存在 `data/bipia/supervised/`；模型、逐样本预测、验证历史、汇总与报告位于 `results/bipia/supervised/`。训练时冻结来源与代码哈希，核验时重新计算所有测试模型分数。

完整指标见 [实验报告](../../results/bipia/supervised/report_ZH.md)。
