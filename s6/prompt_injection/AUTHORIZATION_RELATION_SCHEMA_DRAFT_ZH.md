# 多动作授权关系标注契约草案 v1

日期：2026-10-01。设计草案，不是已实现提取器、已冻结训练schema或新增人工标注。

## 三个独立层次

1. 用户任务：允许做什么、作用对象、禁止项、条件与缺失信息。
2. 文档：实际请求的动作列表、目标描述、引用/假设/实时请求性质。
3. 关系判断：明确冲突、符合已知范围、信息不足；不得由正文自称批准补全用户授权。

任务和正文分别提取，正文提取阶段不读取用户允许的目标来猜正文指代；最后才进行关系判断。数据结构不等于已证明模型能正确完成这些步骤。

## 候选机器字段

- 每侧保留 `actions` 列表，不把多动作压成一个操作字符串。用户侧还应有 `constraints` 和 `missing_context`。
- 每个动作记录原文操作片段、目标提及片段、性质（实时请求／仅计划／模拟／引用／不明确）、证据片段。
- 目标另记录解析状态（明确／文本内指代已解析／歧义／映射缺失／未给定）、已解析标识或null、候选对象及解析依据。
- 原文证据须标明来源侧、起止位置和原文；转换时校验片段与源文本一致。摘要式中文标签不是原文片段，不能冒称逐字证据。
- 操作标准化名称与原文片段分开，不能把“删除”和“清理”等词在没有依据时强行当作等价。
- 动作级关系候选为 `WITHIN_SCOPE`、`CONFLICT`、`UNRESOLVED`、`NON_ACTION_QUOTATION`；整体输出与现有研究三类判定对应，但完整聚合规则需另行冻结与测试。

## 必须保留的语义

- 未知用户授权与未知文档目标分开表示；文档目标明确不能弥补授权缺失。
- 目标候选非授权目标集合。不能因为某个目标获批就选择它作为含糊代词的指代。
- 引用的危险动作可以被抽取为被引用内容，但不能自动变成实时请求。
- 文档可同时含正常引用和新的实时请求，应分别记录。
- 辅助验证/本地输出不是仅凭“会写文件/运行命令”就判风险，也不能凭“通常有帮助”无限扩大授权；判断依赖给定任务边界。
- UNKNOWN不是正常标签。解析失败、证据校验失败和语义信息不足分别记录，均不授予工具执行权限。

## 当前材料与下一步

24条中文范围和动作描述已由用户确认；它们可作为结构转换的语义依据，但新增枚举、原文跨度及拆分后的动作列表仍是技术转换产物，不能宣称已经逐字段人工审核。

这些例子已用于标注规范和输出结构设计。保留原12/6/6组分配，不把保留组加入训练；后续结构泛化结论必须使用新任务组，不能在这些设计样本上宣称独立验证。原验证组没有UNKNOWN样本，扩充时应预先覆盖三类。

接下来先实现版本化schema与转换校验，只对训练种子进行转换调试；再按固定规范扩充与审核材料，冻结后跑训练前对照。不会要求用户重复批准已经确认的同一段中文描述；如转换新增或改变语义，仅对差异请求复核。
